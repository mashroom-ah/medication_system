# «Мой приём» — система учёта лекарств

## Назначение проекта

«Мой приём» — учебное приложение для учёта лекарственных препаратов, расписаний их приёма и истории фактических приёмов. Проект развивается последовательно в рамках практических работ: существующая консольная версия дополнена веб-интерфейсом на Django в рамках практической работы № 5.

Приложение предназначено для людей, которые принимают лекарства по расписанию, а также для тех, кто помогает им контролировать приём.

### Возможности консольной версии

- добавление и поиск пользователей;
- просмотр пользователей и сортировка по возрасту;
- добавление, поиск, фильтрация по дозировке и сортировка лекарств;
- создание и просмотр расписаний приёма;
- проверка наступления времени приёма;
- фиксация фактического приёма лекарства;
- отмена записи о приёме с сохранением истории;
- просмотр записей о приёмах за выбранную дату;
- сохранение данных между запусками в JSON-файлах.

### Возможности веб-интерфейса после ПР5

- просмотр главной страницы и переход к разделам приложения;
- просмотр списка лекарств и поиск по названию;
- просмотр подробной информации об отдельном лекарстве;
- просмотр расписаний с текущим статусом приёма;
- просмотр подробной информации о расписании;
- просмотр истории приёмов и подробной информации о записи;
- отображение страниц ошибки 404 для неизвестных URL и отсутствующих объектов.

Веб-интерфейс на текущем этапе предназначен для просмотра данных. Создание, изменение и удаление записей через веб-формы пока не реализованы; эти операции доступны в консольной версии в соответствии с её функциональностью.

## Используемые технологии

- **Python 3** — язык программирования;
- **Django 5.2** — веб-фреймворк для маршрутизации HTTP-запросов и формирования страниц;
- **HTML** — структура веб-страниц;
- **Bootstrap 5.3** — оформление компонентов и адаптивная навигация, подключаемые через CDN;
- **JSON** — постоянное хранение данных существующего приложения;
- **pytest** — запуск автоматизированных тестов;
- **flake8** — проверка стиля Python-кода.

## Предметная область и основные сущности

Предметная область проекта — персональный учёт лекарств и контроль их приёма. Основные сущности реализованы классами в каталоге `models/`.

- **`User`** (`models/users.py`) — пользователь. Основные атрибуты: `id`, `name`, `age`.
- **`Medicine`** (`models/medicines.py`) — лекарственный препарат. Основные атрибуты: `id`, `name`, `dosage`, `unit`.
- **`Schedule`** (`models/schedules.py`) — расписание приёма препарата. Содержит `id`, ссылки на пользователя и лекарство, а также час и минуту приёма.
- **`Intake`** (`models/intakes.py`) — запись о фактическом приёме. Содержит `id`, ссылку на расписание, дату и признак `taken`.

`Schedule` хранит ссылки на объекты `User` и `Medicine`, а `Intake` — ссылку на `Schedule`. Благодаря этому предметная логика работает с объектами и их связями, а не с наборами несвязанных словарей.

Для преобразования объектов в данные и обратно используются методы `to_data()` и `from_data()`. Проверки и операции над коллекциями реализованы в модулях соответствующих сущностей.

## Основные функции предметной логики

- `add_user()`, `find_user()`, `sort_users()` — добавление, поиск и сортировка пользователей;
- `add_medicine()`, `find_medicine()`, `filter_medicines_by_dosage()`, `sort_medicines()` — работа со списком лекарств;
- `add_schedule()`, `sort_schedules()`, а также методы `Schedule.is_due()` и `Schedule.get_status()` — создание, сортировка и проверка расписаний;
- `create_intake()`, `is_medicine_taken()`, `cancel_intake()`, `get_intakes_by_date()` — регистрация, проверка, отмена и выборка записей о приёмах.

Консольное меню находится в `main.py`. Чтение, запись и восстановление связей между объектами вынесены в `storage.py`. Веб-представления повторно используют эти классы и функции, а не реализуют предметную логику заново.

## Хранение данных

Данные хранятся в JSON-файлах каталога `data/`:

- `users.json` — пользователи;
- `medicines.json` — лекарства;
- `schedules.json` — расписания;
- `intakes.json` — история приёмов.

В файле расписаний сохраняются идентификаторы пользователя и лекарства, а в файле приёмов — идентификатор расписания. При загрузке `storage.py` восстанавливает связи между соответствующими объектами.

В рамках ПР5 существующее JSON-хранилище сохранено. Предметные классы пока не являются Django ORM-моделями; переход к базе данных и Django ORM можно выполнить в следующих практических работах.

## Страницы веб-интерфейса и URL

| URL | Назначение | View-функция |
|---|---|---|
| `/` | Главная страница | `homepage.views.index()` |
| `/medicines/` | Список лекарств и поиск по названию | `medicines.views.medicines()` |
| `/medicines/<medicine_id>/` | Подробная информация о лекарстве | `medicines.views.medicine_detail()` |
| `/schedules/` | Список расписаний и статус приёма | `schedules.views.schedules()` |
| `/schedules/<schedule_id>/` | Подробная информация о расписании | `schedules.views.schedule_detail()` |
| `/intakes/` | История приёмов | `intakes.views.intakes()` |
| `/intakes/<intake_id>/` | Подробная информация о записи | `intakes.views.intake_detail()` |
| `/admin/` | Стандартная административная страница Django | Django Admin |

Для поиска лекарств используется параметр запроса `q`, например: `/medicines/?q=аспирин`. Значения идентификаторов в URL должны соответствовать записям в JSON-файлах.

## Назначение основных view-функций

- **`homepage.views.page(title, content)`** — формирует общий HTML-документ: метаданные страницы, подключение Bootstrap и навигацию. Остальные представления используют эту функцию для единого оформления.
- **`homepage.views.index(request)`** — отображает главную страницу с переходами к основным разделам.
- **`homepage.views.page_not_found(request, exception)`** — формирует страницу ошибки HTTP 404.
- **`medicines.views.medicines(request)`** — загружает лекарства из JSON, при необходимости фильтрует их по названию и отображает список.
- **`medicines.views.medicine_detail(request, medicine_id)`** — отображает карточку лекарства по идентификатору либо возвращает HTTP 404.
- **`schedules.views.schedules(request)`** — загружает расписания и связанные данные, рассчитывает статус приёма и отображает список.
- **`schedules.views.schedule_detail(request, schedule_id)`** — отображает сведения о расписании, пользователе, лекарстве и статусе приёма.
- **`intakes.views.intakes(request)`** — отображает историю приёмов с сортировкой по дате.
- **`intakes.views.intake_detail(request, intake_id)`** — отображает сведения об отдельной записи о приёме либо возвращает HTTP 404.

Маршруты распределены по приложениям: корневые маршруты подключаются в `medication_site/urls.py`, а URL конкретного раздела объявлены в соответствующем `urls.py`. HTML на текущем этапе формируется внутри view-функций через общий `page()`, в соответствии с последовательностью примера раздела 5.4. Использование отдельных Django-шаблонов может быть добавлено позднее.

## Установка и запуск

Команды ниже приведены для Windows PowerShell. Их необходимо выполнять из корневого каталога проекта — там, где находятся `manage.py`, `main.py` и `requirements.txt`.

### 1. Проверить Python

```powershell
py --version
```

### 2. Создать и активировать виртуальное окружение

Создание выполняется один раз:

```powershell
py -m venv venv
```

Активация в PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

Если используется командная строка CMD, команда активации выглядит так:

```bat
venv\Scripts\activate.bat
```

### 3. Установить зависимости

```powershell
python -m pip install -r requirements.txt
```

Проверить установленную версию Django:

```powershell
python -m django --version
```

### 4. Проверить настройки Django

```powershell
python manage.py check
```

### 5. Запустить веб-сервер

```powershell
python manage.py runserver
```

Откройте в браузере адрес `http://127.0.0.1:8000/`. Для остановки сервера нажмите `Ctrl+C` в терминале.

Предметные данные по-прежнему читаются из JSON, поэтому создавать миграции для `User`, `Medicine`, `Schedule` и `Intake` не требуется. При необходимости можно выполнить `python manage.py migrate` для создания служебных таблиц Django.

### Запуск консольной версии

Консольная версия сохранена и запускается отдельно:

```powershell
python main.py
```
