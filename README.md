# «Мой приём» — система учёта лекарств

«Мой приём» — учебное приложение на Python для учёта лекарственных препаратов, расписаний их приёма и истории фактических приёмов. В рамках практической работы № 6 веб-интерфейс Django переведён на систему шаблонов Django Template Language (DTL): HTML-разметка вынесена из Python-представлений в отдельные файлы, добавлены наследование шаблонов, включаемые фрагменты и собственные статические ресурсы.

## 1. Назначение проекта

Проект предназначен для ведения сведений о пользователях, лекарствах, расписаниях и фактических приёмах. Он развивается поэтапно: исходная консольная версия дополнена веб-интерфейсом на Django.

### Возможности консольной версии

- добавление, поиск, просмотр и сортировка пользователей;
- добавление, поиск, фильтрация по дозировке и сортировка лекарств;
- создание и просмотр расписаний приёма;
- проверка наступления времени приёма;
- фиксация фактического приёма лекарства;
- отмена записи о приёме с сохранением истории;
- просмотр записей о приёмах за выбранную дату;
- сохранение данных между запусками в JSON-файлах.

### Возможности веб-интерфейса после ПР6

- просмотр главной страницы и переход к разделам;
- просмотр списка лекарств и поиск по названию;
- просмотр подробной информации об отдельном лекарстве;
- просмотр расписаний и отображение статуса приёма;
- просмотр подробной информации о расписании;
- просмотр истории приёмов и подробной информации о записи;
- отображение страницы ошибки 404 для отсутствующего объекта или неизвестного URL в соответствующих условиях Django.

Веб-интерфейс на текущем этапе предназначен преимущественно для просмотра данных. Создание, изменение и удаление записей через Django-формы не реализованы; операции предметной логики доступны в консольной версии.

## 2. Используемые технологии

- **Python 3** — язык программирования;
- **Django 5.2** — веб-фреймворк;
- **Django Template Language (DTL)** — шаблонизация HTML;
- **HTML5 и CSS3** — структура и оформление страниц;
- **JavaScript** — небольшое динамическое поведение интерфейса;
- **Bootstrap 5.3** — базовые компоненты и адаптивная навигация, подключаемые через CDN;
- **JSON** — хранение предметных данных;
- **pytest** — запуск автоматизированных тестов;
- **flake8** — проверка стиля Python-кода;
- **Git** — контроль версий.

## 3. Предметная область

Предметная область — персональный учёт лекарств и контроль их приёма. Основные сущности реализованы собственными Python-классами в каталоге `models/`:

- **User** (`models/users.py`) — пользователь: идентификатор, имя и возраст;
- **Medicine** (`models/medicines.py`) — лекарственный препарат: идентификатор, название, дозировка и единица измерения;
- **Schedule** (`models/schedules.py`) — расписание приёма, связанное с пользователем и лекарством, с указанием времени;
- **Intake** (`models/intakes.py`) — запись о фактическом приёме, связанная с расписанием, датой и признаком выполнения.

`Schedule` хранит ссылки на объекты `User` и `Medicine`, а `Intake` связан с `Schedule`. Методы `to_data()` и `from_data()` используются для преобразования объектов в данные и обратно. Эти классы являются классами предметной области, а не моделями Django ORM.

## 5. Веб-интерфейс

Веб-часть реализована на Django. Основные страницы:

- главная страница;
- список лекарств и страница отдельного лекарства;
- список расписаний и страница отдельного расписания;
- история приёмов и страница отдельной записи.

Представления подготавливают данные и передают их в шаблоны через контекст с помощью `render()`. Генерация HTML-строк непосредственно в `views.py` не используется; вспомогательная функция `page()` из предыдущей версии больше не нужна.

### URL и представления

| URL | Назначение | View-функция |
|---|---|---|
| `/` | Главная страница | `homepage.views.index()` |
| `/medicines/` | Список лекарств и поиск по названию | `medicines.views.medicines()` |
| `/medicines/<medicine_id>/` | Подробная информация о лекарстве | `medicines.views.medicine_detail()` |
| `/schedules/` | Список расписаний и статусы | `schedules.views.schedules()` |
| `/schedules/<schedule_id>/` | Подробная информация о расписании | `schedules.views.schedule_detail()` |
| `/intakes/` | История приёмов | `intakes.views.intakes()` |
| `/intakes/<intake_id>/` | Подробная информация о записи | `intakes.views.intake_detail()` |
| `/admin/` | Стандартная административная страница Django | Django Admin |

Поиск лекарств выполняется по параметру `q`, например: `/medicines/?q=аспирин`.

## 6. Django Template Language (DTL)

### Базовый шаблон и наследование

Общий шаблон находится в `templates/base.html`. Он содержит базовую HTML-структуру, подключение Bootstrap и собственных статических файлов, навигацию, блоки заголовка и основного содержимого, а также подвал.

Дочерние шаблоны используют наследование:

```django
{% extends "base.html" %}
```

Заголовок страницы и её содержимое задаются блоками:

```django
{% block title %}Название страницы{% endblock %}
{% block content %}
    <!-- Содержимое конкретной страницы -->
{% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные файлы и подключаются директивой `{% include %}`:

- `templates/includes/navigation.html` — основная навигация;
- `medicines/templates/medicines/includes/medicine_card.html` — карточка лекарства;
- `schedules/templates/schedules/includes/schedule_card.html` — карточка расписания;
- `intakes/templates/intakes/includes/intake_status.html` — отображение статуса записи о приёме.

### Контекст, циклы и условия

Представления передают данные в шаблоны через словарь контекста. В шаблонах используются `{{ ... }}` для вывода значений объектов, `{% for %}` для перебора списков, `{% if %}` для условий и `{% empty %}` для отображения сообщения, когда коллекция пуста. Детальные страницы обрабатывают отсутствующие объекты и возвращают HTTP 404.

### Фильтры шаблонов

В шаблонах используются стандартные фильтры DTL, в том числе:

```django
{{ medicines|length }}
{{ medicine.name|default:"Без названия" }}
```

Фильтр `length` позволяет вывести количество элементов, а `default` — подставить значение, если исходное значение отсутствует или пустое. Фильтры используются для представления данных, а не для реализации бизнес-логики.

## 7. URL-маршрутизация

Корневые маршруты подключаются в `medication_site/urls.py`, а маршруты конкретных приложений объявляются в их собственных файлах `urls.py`. Каждое приложение задаёт `app_name` и имена маршрутов.

Примеры именованных URL:

```django
{% url 'homepage:index' %}
{% url 'medicines:list' %}
{% url 'medicines:detail' medicine.id %}
{% url 'schedules:list' %}
{% url 'schedules:detail' schedule.id %}
{% url 'intakes:list' %}
{% url 'intakes:detail' intake.id %}
```

Пространства имён `homepage`, `medicines`, `schedules` и `intakes` позволяют однозначно ссылаться на маршруты разных приложений. В шаблонах используются `{% url %}`, а не жёстко заданные адреса внутренних страниц.

## 8. Статические файлы

Собственные статические ресурсы находятся в каталоге `homepage/static/homepage/`:

- `css/style.css` — оформление интерфейса;
- `img/logo.svg` — логотип;
- `js/main.js` — небольшая динамика интерфейса, включая автоматическую подстановку текущего года в подвал.

В шаблонах используется `{% load static %}`. Ресурсы подключаются, например, так:

```django
{% load static %}
<link rel="stylesheet" href="{% static 'homepage/css/style.css' %}">
<img src="{% static 'homepage/img/logo.svg' %}" alt="Логотип проекта">
<script src="{% static 'homepage/js/main.js' %}"></script>
```

Внутренняя папка `homepage` после `static` является пространством имён статических файлов приложения и помогает избегать совпадения имён ресурсов, если в других приложениях появятся файлы с такими же названиями. Bootstrap CSS и JavaScript подключаются через CDN, а собственный CSS дополняет оформление.

## 9. Хранение данных

Предметные данные хранятся в JSON-файлах каталога `data/`:

- `users.json` — пользователи;
- `medicines.json` — лекарства;
- `schedules.json` — расписания;
- `intakes.json` — история приёмов.

Загрузка и сохранение выполняются через `storage.py`. В JSON хранятся идентификаторы связанных объектов; при загрузке приложение восстанавливает связи между экземплярами `User`, `Medicine`, `Schedule` и `Intake`.

Django ORM и база данных для предметных сущностей пока не используются. Стандартные файлы `models.py` внутри Django-приложений сохранены, но предметные классы находятся в каталоге `models/`. Переход к ORM и базе данных относится к следующим этапам развития проекта.

## 10. Основные модули

- `models/` — собственные классы предметной области `User`, `Medicine`, `Schedule`, `Intake`;
- `storage.py` — загрузка и сохранение JSON, восстановление связей между объектами;
- `main.py` — консольное меню и операции пользователя;
- `utils.py` — вспомогательные функции консольного интерфейса;
- `medication_site/settings.py` — настройки Django, включая поиск шаблонов и статических файлов;
- `medication_site/urls.py` — корневая маршрутизация;
- `homepage/views.py` — главная страница и обработчик 404;
- `medicines/views.py` — список лекарств и детальная страница;
- `schedules/views.py` — список расписаний, вычисление и отображение статусов, детальная страница;
- `intakes/views.py` — список истории приёмов и детальная страница.

## 13. Установка и запуск

Инструкции ниже приведены для Windows PowerShell. Команды необходимо выполнять из корневого каталога, в котором находится `manage.py`.

### 1. Проверить Python

```powershell
py --version
```

### 2. Создать и активировать виртуальное окружение

Создание окружения выполняется один раз:

```powershell
py -m venv venv
```

Активация в PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

### 3. Установить зависимости

```powershell
python -m pip install -r requirements.txt
```

Проверить версию Django можно командой:

```powershell
python -m django --version
```

### 4. Проверить настройки и запустить сервер

```powershell
python manage.py check
python manage.py runserver
```

Откройте в браузере `http://127.0.0.1:8000/`. Для остановки сервера нажмите `Ctrl+C` в терминале. Пример URL поиска: `http://127.0.0.1:8000/medicines/?q=аспирин`.

При необходимости можно выполнить `python manage.py migrate` для создания служебных таблиц Django. Это не переносит предметные JSON-данные в базу данных и не заменяет существующее хранилище.

### Запуск консольной версии

Консольная версия сохраняется и запускается отдельно:

```powershell
python main.py
```
